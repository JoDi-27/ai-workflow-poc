# Claude Code setup

What this repository adds to Claude Code: skills, agents, hooks, and permissions. Claude Code reads them from this folder; nothing here is product code. The skills and the agent make up the spec kit, described in `specs/README.md`.

The sections between the markers below are generated by `.claude/bom.py` from the files themselves, so they cannot drift:

- **Skills and agents:** the `name`, `description`, `argument-hint`, and `tools` in each file's frontmatter.
- **Hooks:** `settings.json`, plus line 2 of each hook script, a comment in the form `# <Event> on <matcher>: <what it does>`.
- **Permissions:** the `allow` list in `settings.json`.

A hook (`hooks/post-edit-bom.sh`) reruns the script whenever Claude edits a file in this folder, and the session-start hook warns when the inventory is out of date, for example after an edit made outside Claude. To regenerate it by hand, run `.claude/bom.py`.

## Adding something

- **Skill:** `skills/<name>/SKILL.md` with `name`, `description`, and `argument-hint` in its frontmatter.
- **Agent:** `agents/<name>.md` with `name`, `description`, and `tools` in its frontmatter.
- **Hook:** a script in `hooks/` whose line 2 is the header comment above, registered in `settings.json` as `"$CLAUDE_PROJECT_DIR"/.claude/hooks/<script>`. The hooks need `jq` and `python3`.
- **Permission:** an entry in the `allow` list of `settings.json`.

Personal settings go in `settings.local.json`, which git ignores; they are not listed here.

## Skills

| Skill | Arguments | Use it for |
| --- | --- | --- |
| `/sdd-implement` | `<spec ID> [task ID, e.g. T3]` | Implement a planned feature spec task by task, ticking each task only when its check passes. Use when a spec in specs/ is planned or in progress. |
| `/sdd-plan` | `<spec ID>` | Approve a spec and write its technical plan (plan.md) and task list (tasks.md). Use when a feature spec in specs/ is ready to be planned; spikes are run with /sdd-spike instead. |
| `/sdd-specify` | `<idea \| PLAN.md item \| spec ID>` | Create a new feature spec in specs/, or refine and clarify an existing one. Use when starting a new piece of work or picking up a PLAN.md item; spikes go to /sdd-spike. |
| `/sdd-spike` | `<spike ID \| topic> [new information]` | Run a spike as an interview with the user. Prepares a briefing and questions with the spike-researcher agent, asks them in small batches, records answers and any information the user adds as it comes, and keeps going until the spike's goal questions are resolved. Use for any spike spec, any PLAN.md Phase 0 spike, or whenever the user adds information about an active spike. |
| `/sdd-status` | `[spec ID]` | Show the progress board of specs in specs/ and what to work on next, or the detailed state of one spec. Use when asked about progress, status, or what to do next. |
| `/sdd-verify` | `<spec ID>` | Verify a spec's acceptance criteria (or a spike's answers) with evidence, then close it and update PLAN.md and BACKLOG.md. Use when all of a spec's tasks are ticked. |

## Agents

| Agent | Tools | Use it for |
| --- | --- | --- |
| `spike-researcher` | Read, Grep, Glob, WebSearch, WebFetch | Use this agent to prepare a spike in specs/ for an interview with the user, or to research a factual question that came up during one. It gathers what the repository docs and current external docs already say about the spike's goal questions, settles the factual unknowns it can, and drafts a prioritized bank of questions that only the user can answer. Read-only; it returns a report and never edits files. Launched by the /sdd-spike skill. |

## Hooks

| Event | Matcher | Script | Does |
| --- | --- | --- | --- |
| `SessionStart` | all | `hooks/session-start.sh` | Print the spec board, the claims, and any stale .claude/README.md warning into context (stdout is added as context). |
| `PreToolUse` | Bash | `hooks/pre-commit-message.sh` | Block `git commit` whose message does not start with `[NNN]`, `[NNN] Tn`, or `[meta]`. |
| `PostToolUse` | Edit\|Write | `hooks/post-edit-status.sh` | Regenerate specs/STATUS.md when a spec.md or tasks.md changed. |
| `PostToolUse` | Edit\|Write | `hooks/post-edit-bom.sh` | Regenerate the inventory in .claude/README.md when a skill, agent, hook, or settings.json changed. |
| `Stop` | all | `hooks/stop-claims.sh` | Warn (never block) when this session still holds sdd claims. |
