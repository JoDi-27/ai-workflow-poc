# ai-workflow-poc

Working rules for Claude Code sessions in this repository. What the project is, its stack, and where to read are in `README.md`; this file only says how to work here.

## How work is done

All work goes through the spec-driven kit in `specs/`. The `/sdd-*` skills handle claims, status upkeep, library checks, and the `BACKLOG.md` and `PLAN.md` updates; `specs/README.md` explains the kit. These rules hold even when no skill is running:

- Do not implement anything that has no spec in `specs/`. Create one with `/sdd-specify` first, even for small items; a short feature spec is fine.
- Features follow `/sdd-specify` → `/sdd-plan` → `/sdd-implement` → `/sdd-verify`, and spikes follow `/sdd-spike` → `/sdd-verify`. Stop at the end of each step for the user's review; running the next command is the approval.
- Whenever the user shares information about an active spike, even outside the command, record it in that spike's Log and Findings.
- When code and spec disagree, update the spec or plan first, then the code (constitution, article 13).

## Conventions

- Changes reach `main` only through a pull request whose required checks pass; never push to `main`. `CONTRIBUTING.md` has the steps.
- Commit only when asked. Messages start with the spec and task ID, for example `[003] T2 Add run state table`. Use `[meta]` only for housekeeping that changes no behavior or requirements (hooks, settings, kit scripts, doc fixes); anything else needs a spec. Keep the first line to 72 characters or fewer, imperative, and add a body only to explain why. `CONTRIBUTING.md` has the full format.
- Docs are written in plain, short sentences, consistent with the existing Markdown files. Add each new document to `docs/README.md`.
- Name spikes by their spec ID (spike 010), never by an older number.
- When you add a skill, agent, hook, or permission, follow "Adding something" in `.claude/README.md`. The inventory there regenerates itself; never edit it by hand.
- Specs, plans, and tasks follow the practices in `specs/README.md` ("Good practices this kit enforces").
