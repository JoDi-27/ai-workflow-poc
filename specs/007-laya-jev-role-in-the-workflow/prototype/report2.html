Does it rate bad code low?
Laya: its median ranks good above flawed in 3/5 pairs, but by at most 0.4 points (mean gap -0.0). It answers almost the same for both variants of every task. Its has a defect question "catches" every flawed variant only because it says "defect" for every case, good ones included. It does not tell bad code from good.
Jev: its median ranks good above flawed in 5/5 pairs (mean gap 2.5), but puts only 2/5 flawed variants below the pass mark. Its has a defect question alone puts 5/5 flawed variants below 6 and keeps 5/5 good ones at 6 or above. The lenient questions (criteria met, quality band) pull the median up, so a median hides the defect signal.

The questions

Each model got all four questions in one request per case. None names a case's planted flaw.

QuestionTypeInstructions and optionsMapped to 1–10 as
criteria_metscoreHow completely does the code change implement the acceptance criteria in the requirements?
0: Implements none of the acceptance criteria.
1: Implements a few of the acceptance criteria.
2: Implements most acceptance criteria, but at least one is missing or implemented wrongly.
3: Implements every acceptance criterion, with minor gaps.
4: Implements every acceptance criterion exactly.
1 + 9 × level / 4 (level 0–4, from the expected position)
tests_covernoulDo the tests in the change check every acceptance criterion, including the edge cases the requirements name?
false: At least one acceptance criterion or named edge case has no test.
true: Every acceptance criterion and named edge case has a test.
1 + 9 × P(true)
has_defectnoulDoes the change contain a defect: behavior that contradicts the requirements for some input, a security flaw such as SQL injection, or a behavior change the requirements did not ask for?
false: The code behaves as the requirements say for every input, with no security flaw and no unrequested behavior change.
true: The code contradicts the requirements for some input, has a security flaw, or changes behavior that was not asked for.
1 + 9 × (1 − P(true)): a likely defect means a low score
code_quality_bandchoiceWhich band of the code quality rubric does this change fall in? Judge the change against the requirements, not against your own design.
poor: Does not meet the requirements, or is unreadable.
weak: Meets most requirements, with clear correctness or structure problems.
good: Meets the requirements; readable, with minor issues only.
exemplary: Meets the requirements; idiomatic, well-factored, and easy to extend.
Expected value of the band midpoints: poor 2, weak 4.5, good 7, exemplary 9.5
